# DTStoMKV

Конвертер аудио в Matroska для **Linux и Windows**, Python 3.10+.
Общий движок используется графическим интерфейсом Tkinter и командной строкой.

Возможности:

- LPCM 16/24/32 bit, FLAC, AC3 и TrueHD; выбор частоты, сохранение числа каналов.
- Конвертация без видео, копирование первой видеодорожки или цветная визуализация
  AV1, HEVC / H.265, VP9 либо H.264.
- Главы и названия треков из однофайлового CUE, UTF-8/BOM и Windows-1251.
- Визуализация с названием альбома, текущего трека, общим таймером и цветом по анализу аудио.
- Формат исходного и выходного звука в журнале во всех режимах, включая пакетный;
  формат результата также отображается в визуализации.
- Перенос длинных названий треков в две строки по ширине выбранного TTF-шрифта;
  для очень длинных названий размер шрифта уменьшается до размещения на экране.
- Пакетная обработка папки, автоматический поиск одноимённого CUE, остановка обработки.
- Автоматическое имя результата совпадает с исходным; меняется только расширение на `.mkv`.
- Прогресс кодирования в журнале GUI и CLI: процент, обработанное время и скорость.
- Существующие результаты защищены от перезаписи по умолчанию; при отмене временные файлы удаляются.

Обрабатывается первый аудиопоток; в режиме копирования — первый видеопоток.
Субтитры, вложения и дополнительные аудиопотоки в результат не переносятся.
Частые входные форматы: WAV (включая DTS-CD), DTS, MLP, AOB, MKV, MKA, TS, FLAC, AC3.
Доступность декодеров и кодировщиков определяется установленной сборкой FFmpeg.

## Linux

Пример для Debian/Ubuntu:

```bash
sudo apt install python3-venv python3-tk ffmpeg fonts-dejavu-core
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m dtstomkv gui
```

Для других дистрибутивов установите Python с Tkinter, FFmpeg/ffprobe и TTF-шрифт
с кириллицей средствами своего пакетного менеджера.

## Windows

Установите Python 3.10+ с компонентом Tcl/Tk и FFmpeg. Добавьте каталог `bin`,
содержащий `ffmpeg.exe` и `ffprobe.exe`, в PATH. В PowerShell из папки проекта:

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe -m dtstomkv gui
```

Старый запуск `python DTStoMKV_gui.py` также работает на обеих ОС.

## Командная строка

```bash
python -m dtstomkv convert input.dts output.mkv
python -m dtstomkv convert input.dts
python -m dtstomkv convert input.mkv /path/to/existing/output-folder/
python -m dtstomkv convert input.mkv output.mkv --video copy --bit-depth 24
python -m dtstomkv convert album.wav album.mkv --video visual --cue album.cue --album "Название альбома"
python -m dtstomkv convert album.wav album-av1.mkv --video visual --video-profile av1
python -m dtstomkv convert album.wav album-hevc.mkv --video visual --video-profile hevc
python -m dtstomkv convert album.wav album-vp9.mkv --video visual --video-profile vp9
python -m dtstomkv convert input.wav output.mkv --codec flac --flac-level 8
python -m dtstomkv convert input.wav output.mkv --codec ac3 --bitrate 640k --sample-rate 48000
python -m dtstomkv convert input.wav output.mkv --codec truehd --sample-rate 48000
python -m dtstomkv convert --help
```

Для разрешённой перезаписи добавьте `--overwrite` или включите соответствующий
флажок в GUI. `Ctrl+C` останавливает CLI и завершает дочерний процесс.
В GUI закрытие окна во время работы сначала останавливает FFmpeg и очищает временные файлы.
Выходной файл не может совпадать с входным.
Без выходного пути CLI создаёт `<имя исходного файла>.mkv` рядом с источником.
Если указана существующая папка, в ней создаётся файл с тем же именем и расширением
`.mkv`. Явно заданное имя файла в CLI по-прежнему поддерживается.
В GUI выбор или изменение исходного файла автоматически подставляет имя результата;
если ранее выбрана другая папка сохранения, она сохраняется. Выходной путь можно
изменить вручную. Для входного MKV выберите другую папку, чтобы сохранить исходник.

Во время кодирования журнал обновляется примерно раз в секунду, например:
`Кодирование: 42.5% · 00:12:45 / 00:30:00 · скорость 2.1x`.
Прогресс получен из `-progress` FFmpeg и доступен для всех профилей, аудио без видео
и копирования видео. Если длительность неизвестна, выводятся время и скорость.
100% появляется только после успешного завершения кодировщика; при ошибке или
отмене сообщение об успешном завершении не выводится.

FFmpeg и ffprobe ищутся через PATH. Произвольные пути задаются переменными
`DTSTOMKV_FFMPEG`, `DTSTOMKV_FFPROBE`, `DTSTOMKV_FONT` либо параметрами CLI
`--ffmpeg`, `--ffprobe`, `--font`. В GUI используются те же переменные окружения.
Автоматический шрифт: Arial в Windows, DejaVu Sans в Linux.
Визуализация требует фильтр `drawtext` и кодировщик выбранного профиля:

| Профиль CLI | Вариант в GUI | Параметры |
| --- | --- | --- |
| `av1` | AV1 — libaom, screen, CRF 24 | `libaom-av1`, `-aom-params tune-content=screen -crf 24 -b:v 0` |
| `hevc` | HEVC / H.265 — x265 slow, CRF 27 | `libx265`, `-preset slow -crf 27` |
| `vp9` | VP9 — libvpx, screen, CRF 17 | `libvpx-vp9`, `-tune-content screen -crf 17 -b:v 0` |
| `h264` | H.264 — прежний вариант, по умолчанию | `libx264`, `-preset ultrafast -tune stillimage -crf 23` |

Выбор доступен в параметрах визуализации всех трёх вкладок GUI, в том числе
для пакетной обработки. Профили одинаковы в Linux и Windows; наличие библиотек
определяется сборкой FFmpeg. Если кодировщика нет, приложение сообщает его имя
до анализа треков; автоматической замены кодека нет. Проверка не нужна для режимов
без видео и копирования видео.
У новых профилей параметры фиксированы; CLI-параметры `--crf` и `--preset`
по-прежнему изменяют только профиль `h264`. FPS и разрешение применяются ко всем
профилям. `-b:v 0` включает режим постоянного качества без заданного видеобитрейта
для AV1/VP9. Подробнее: [документация кодировщиков FFmpeg](https://ffmpeg.org/ffmpeg-codecs.html).

Проверено с FFmpeg/ffprobe 9.0.2. Для FFmpeg 7+ граф фильтров загружается через
`-/filter:v`; для более ранних версий используется `-filter:v` с содержимым графа.
Удалённый в FFmpeg 9 параметр `-filter_script:v` больше не используется.
Для измерения текста используется Pillow (устанавливается вместе с приложением).

Для AC3 поддерживаются до 6 каналов и частоты 32/44.1/48 кГц. TrueHD включается
с `-strict experimental`; приложение ограничивает его шестью каналами и частотами
44.1/48 кГц. Автоматического понижения частоты или числа каналов нет.
`Auto` сохраняет определённую FFprobe битность; если она неизвестна, для DTS,
MLP, TrueHD и FLAC выбираются 24 bit, для остальных — 16 bit.
Это выбор формата PCM, а не восстановление информации, отсутствующей в источнике.

Пакетный режим обрабатывает только выбранную папку, без рекурсии. Все файлы,
включая входные MKV, получают имя `<имя>.mkv` без дополнительных суффиксов.
Для MKV нужна другая папка сохранения. При совпадении входной и выходной папок
MKV, у которых рядом есть одноимённый исходник с другим расширением, исключаются
из списка, чтобы не конвертировать результаты повторно. Если два источника
получают одно выходное имя (например, `album.wav` и `album.flac`), обработка
не запускается: переименуйте один из источников или обрабатывайте их раздельно.

## Архитектура и очистка

| Файл | Назначение |
| --- | --- |
| `dtstomkv/core.py` | Опции, запуск/отмена FFmpeg, конвертация, анализ и визуализация |
| `dtstomkv/cue.py` | Разбор CUE, проверка таймингов, сериализация глав |
| `dtstomkv/runtime.py` | Поиск программ и шрифтов, параметры запуска для ОС |
| `dtstomkv/gui.py` | Три вкладки Tkinter; снимок настроек перед запуском потока, очередь событий |
| `dtstomkv/__main__.py` | CLI и запуск GUI |
| `DTStoMKV_gui.py` | Совместимый старый способ запуска |

Удалены ранние реализации `make_demo.py`, `make_demo_gui.py`, `make_demo_gui2.py`
и обёртки `make_demo_ac3.py`, `make_demo_flac.py`, `make_demo_truehd.py`.
Их кодеки объединены в общем движке; параметры FPS, CRF, preset, битрейта и уровня
FLAC доступны в CLI. Вместо склейки отдельных MKV визуализация создаётся за один
проход, аудио не режется на сегменты. Анализ цвета использует до 30 секунд каждого
трека и NumPy; для длинных треков выбираются три фрагмента по 10 секунд из разных
частей трека. Оттенок зависит от спектрального центра, долей баса и высоких частот,
изменений спектра; насыщенность и яркость — также от громкости и пик-фактора.
Одинаковое содержимое получает одинаковый цвет независимо от порядка треков;
тёмная палитра сохраняет контраст белых надписей.
Зависимости librosa и SoundFile больше не нужны.
Титры читаются из текстовых файлов, поэтому кавычки, двоеточия и `%` не ломают фильтры.
Личный `make_demo_gui.json` с путями к диску D: и `convert-to-mkv.txt` с разовой
командой заменены примерами выше. Автосохранение настроек старого demo-GUI не переносится.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Тесты генерируют короткие аудио/видеофайлы и проверяют все четыре аудиокодека,
главы, кириллицу и спецсимволы, копирование видео из DTS-контейнера,
четыре профиля визуализации, CLI, отмену и защиту выходных файлов. Для профилей
проверяются декодирование видео, сохранность аудио и глав. Нужны FFmpeg и ffprobe.
Проверки отсутствующих в сборке видеокодировщиков пропускаются.
Без них интеграционные проверки пропускаются.
Отдельная проверка GUI: `python tests/gui_smoke.py` (нужен дисплей; Linux —
`xvfb-run -a python tests/gui_smoke.py`). Workflow GitHub Actions запускает проверки
на Linux и Windows с Python 3.10 и 3.13.
